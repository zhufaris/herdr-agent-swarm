# TraeX Shim Lifecycle Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make a bridge-created TraeX process immediately usable through Herdr's Agent API without restoring terminal reads or prompt fallbacks.

**Architecture:** The process-fenced shim reporter claims an initial Codex-compatible `idle` authority and projects it as TraeX. A separate stdin-driven TraeX hook maps only `UserPromptSubmit` to `working` and `Stop` to `idle`, while official `herdr agent prompt --wait` remains the sole prompt submission and settlement mechanism.

**Tech Stack:** TypeScript ESM, Node.js 22+, Vitest, TraeX hooks, Herdr 0.7.5 CLI.

**Spec:** `docs/superpowers/specs/2026-08-29-terminal-read-free-herdr-control-design.md`

## Global Constraints

- Do not call `pane read`, `agent read`, `agent explain`, `pane send-text`, or raw Pane Enter.
- Keep process identity fenced by pane ID, PID, `/proc/<pid>/exe`, and start ticks.
- Keep the internal authority agent as `codex` and expose only marked entries as `traex`.
- Never automatically replay a prompt after the Herdr prompt process may have started.
- Hook input must be bounded and validated; prompt and answer content must never be logged.
- Preserve the existing bridge-owned `SessionStart` session UUID reporter.
