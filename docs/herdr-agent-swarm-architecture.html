Herdr Agent Swarm · 项目架构

从 Lark 入站到 TraeX 执行、持久化投影与 CardKit 回传；同时标出权威来源、恢复闭环和首要排障入口。

状态冲突时相信谁

  • • pane、进程与 agent runtime：Herdr fresh snapshot
  • • active-turn 输出与 token：精确匹配的 TraeX transcript
  • • workflow intent、队列、投影、outbox：SQLite
  • • standalone service 生命周期：user systemd

请求卡住时先查什么

  • • 用 eventId / bindingId / promptId / paneId / replyId 关联日志
  • • 检查 inbound → prompt/checkpoint → projection → outbox
  • • 再与 fresh Herdr snapshot 和精确 transcript 对照
  • • socket/work hint 丢失只影响延迟，不改变 durable truth

必须保持的不变量

  • • 每个 binding 同时最多一个 ordinary turn；其余严格 FIFO
  • • uncertain dispatch 或 restart 后绝不自动重放 prompt
  • • Lark 投递前持久化 intent；delivery retry 不重复 TraeX prompt
  • • CardKit stream 有序；冻结页不可 patch；高风险审批仅留在 Herdr
