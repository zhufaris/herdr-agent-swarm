# Terminal Fallback Warning Implementation Plan

> **For agentic workers:** Implement inline in the current session. Keep the existing dirty worktree intact and do not alter pane processes.

**Goal:** Make every Answer produced from Herdr pane fallback visibly identify that degraded source, while leaving JSONL typed answers unchanged.

**Architecture:** `PromptRunWorkflow` owns source selection, so it also owns the user-facing fallback notice. A terminal source tracks whether its notice has been projected. Initial terminal selection and pre-output typed-read failure publish the notice once; terminal `replace-all` snapshots re-prefix it because that reducer operation replaces the full answer. Finalization normalizes the notice to exactly one copy.

**Tech Stack:** TypeScript, Vitest, SQLite-backed integration tests

**Spec:** User-approved inline design from 2026-08-27: fixed warning at the top of terminal fallback answers; never shown for typed JSONL output.

## Global Constraints

- The warning text is: `> ⚠️ 未能读取 TraeX JSONL，以下内容来自 Herdr pane fallback，可能缺少工具调用结构或完整上下文。`
- Do not expose internal fallback reason codes in Lark.
- Do not mix terminal content into a typed answer after typed output has been emitted.
- Persist the warning in the canonical run-card answer so pagination and restart recovery preserve it.
- Emit the warning exactly once in the visible answer, including after terminal `replace-all` updates.
